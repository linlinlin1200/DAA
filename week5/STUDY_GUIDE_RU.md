# Week 5: как объяснить решения

Подробные отчёты на английском: [массив](sort_an_array/README.md) и [связный список](sort_list/README.md). Здесь — краткое объяснение для подготовки к обсуждению.

## Общая идея сортировки слиянием

Две уже отсортированные последовательности можно объединить за линейное время. Сравниваются их первые ещё не использованные элементы; меньший добавляется к результату. Когда одна последовательность заканчивается, остаток другой переносится целиком. Каждый элемент обрабатывается ограниченное число раз.

Например, слияние `[2, 5]` и `[1, 3]`:

```text
2 сравнивается с 1 → берём 1 → [1]
2 сравнивается с 3 → берём 2 → [1, 2]
5 сравнивается с 3 → берём 3 → [1, 2, 3]
правая часть закончилась → добавляем 5 → [1, 2, 3, 5]
```

Инвариант слияния: уже собранная часть отсортирована и содержит наименьшие из обработанных элементов. Следующим всегда выбирается наименьший из двух доступных элементов. Поэтому порядок сохраняется на каждом шаге.

## 1. Sort an Array

Массив делится на две части, каждая рекурсивно сортируется, затем они сливаются. Часть длины 0 или 1 уже отсортирована.

```text
[5, 2, 3, 1]
       ↓ деление
[5, 2]         [3, 1]
   ↓               ↓
[5] [2]        [3] [1]
   ↓ слияние        ↓
[2, 5]         [1, 3]
       ↓ слияние
[1, 2, 3, 5]
```

В коде границы части задаются индексами: начало включается, конец не включается. Временный буфер создаётся один раз на весь массив и используется во всех слияниях. После слияния результат копируется из буфера в соответствующую часть исходного массива.

**Почему O(n log n):** число уровней деления пропорционально log n; суммарная работа на каждом уровне — O(n), поскольку части не пересекаются. Получается O(n) × O(log n). Возврат того же объекта массива не означает O(1) памяти: буфер занимает O(n), стек рекурсии — O(log n), вместе O(n).

**Возможное улучшение:** heapsort сохраняет O(n log n) времени и уменьшает дополнительную память до O(1), но обычно не сохраняет взаимный порядок элементов с равными ключами. В этой реализации слияние стабильно: при равенстве выбирается элемент слева.

## 2. Sort List

У узла связного списка есть значение `val` и ссылка `next`. Здесь применяется итеративная сортировка слиянием: сначала сливаются соседние серии длины 1, затем 2, затем 4 и так далее. Последняя серия может оказаться короче.

```text
4 → 2 → 1 → 3

ширина 1: [4] + [2] → [2, 4]; [1] + [3] → [1, 3]
получается: 2 → 4 → 1 → 3

ширина 2: [2, 4] + [1, 3] → [1, 2, 3, 4]
получается: 1 → 2 → 3 → 4
```

Серии нужно отсоединять от остального списка: конец каждой серии получает `next = None`. Ссылку на следующую серию предварительно сохраняют. Иначе слияние может выйти за границы своей серии, потерять узлы или создать цикл.

Переставляются ссылки между существующими узлами. Значения не переписываются, массив из узлов не создаётся. Вспомогательный узел перед началом списка упрощает присоединение первого элемента результата.

**Почему O(n log n):** ширина удваивается, поэтому проходов O(log n). За один проход разбиение и слияние всех серий требуют O(n) работы. Предварительный подсчёт длины требует O(n) и не меняет итоговую оценку.

**Почему O(1) дополнительной памяти:** число одновременно используемых ссылок и вспомогательных узлов ограничено константой. Рекурсивных вызовов и буфера размера n нет. Исходные n узлов — входные данные, а не дополнительная память.

## Как проверить понимание

1. Выписать руками все сравнения при слиянии `[1, 4, 4]` и `[2, 4]`.
2. Объяснить, почему `<=` сохраняет порядок одинаковых элементов.
3. Показать серии на каждом проходе для списка `5 → -1 → 3 → 0 → 2`.
4. Объяснить, зачем сохранить следующую серию до изменения `next`.
5. Назвать отдельно время, дополнительную память и причину каждой оценки.
6. Запустить тесты и объяснить, какие ошибки находят проверки циклов и идентичности узлов.

Для сравнения: простая сортировка соседними обменами может требовать O(n²) времени. Уже отсортированные части позволяют слиянию избежать многократного поиска следующего минимального элемента. Для произвольных ключей в модели сравнений O(n log n) — оптимальная оценка худшего случая; при дополнительных ограничениях на значения возможны другие алгоритмы, например counting sort за O(n + k) времени и O(k) дополнительной памяти, где k — размер диапазона значений.
