# 94. Binary Tree Inorder Traversal

[Условие на LeetCode](https://leetcode.com/problems/binary-tree-inorder-traversal/)

## 1. Problem

Нужно получить значения узлов в порядке «левое поддерево — узел — правое поддерево». Для пустого дерева ответ — пустой список.

## 2. Approach

Используется стек вместо рекурсии. Сначала спускаемся по левым детям и сохраняем узлы в стеке. Когда левее идти нельзя, достаём узел, добавляем его значение в ответ и переходим к его правому ребёнку. Стек помогает вернуться к ещё не обработанным родителям.

Пример: `[1, null, 2, 3]`. У узла `1` есть правый ребёнок `2`, а у `2` — левый ребёнок `3`. В таблице вершина стека справа.

| Шаг | Действие | Стек | Ответ |
| --- | --- | --- | --- |
| 1 | Сохраняем `1`, его левый ребёнок пуст | `[1]` | `[]` |
| 2 | Достаём `1`, идём вправо к `2` | `[]` | `[1]` |
| 3 | Сохраняем `2`, затем `3` | `[2, 3]` | `[1]` |
| 4 | Достаём `3`, затем `2` | `[]` | `[1, 3, 2]` |

Легко перепутать обход с сортировкой: бинарное дерево не обязательно является деревом поиска. Для `[2, 3, 1]` сортировка даёт `[1, 2, 3]`, а правильный обход — `[3, 2, 1]`. Этот неверный вариант проверяется в тестах.

## 3. Time Complexity

**Время: O(n)**, где `n` — число узлов. Каждый узел ровно один раз попадает в стек, извлекается из него и добавляется в результат. Вложенные циклы не дают O(n²), потому что повторного обхода одних и тех же узлов нет.

**Дополнительная память: O(h)** для стека, где `h` — высота дерева. Возвращаемый список занимает ещё O(n); с учётом результата общая память O(n).

## 4. Reflection / Improvement

По времени лучше O(n) получить нельзя: нужно вернуть все значения. Обход Морриса позволяет сократить дополнительную память до O(1), временно меняя ссылки дерева. Здесь стек проще объяснить и не требует менять дерево.

В `TestCases.java` есть пустое дерево, один узел, отрицательные и повторяющиеся значения, цепочки из 100 узлов и 300 случайных деревьев. Для случайных примеров ответ сравнивается с рекурсивным обходом; также проверяется сохранность дерева. Это локальные проверки, а не отправка в LeetCode.
