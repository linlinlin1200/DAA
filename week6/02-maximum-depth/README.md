# 104. Maximum Depth of Binary Tree

[Условие на LeetCode](https://leetcode.com/problems/maximum-depth-of-binary-tree/)

## 1. Problem

Нужно найти число узлов на самом длинном пути от корня до листа. Глубина пустого дерева равна `0`, а дерева из одного узла — `1`.

## 2. Approach

Используется обход в глубину со стеком. Вместе с каждым узлом сохраняется его глубина. Начинаем с корня на глубине `1`. Достаём очередной узел, обновляем максимум и добавляем его детей с глубиной на единицу больше.

Итеративный вариант выбран, чтобы длинная цепочка не переполнила стек рекурсивных вызовов Java. Правый ребёнок добавляется первым, поэтому левый обрабатывается раньше; на значение максимальной глубины порядок не влияет.

Пример: `[3, 9, 20, null, null, 15, 7]`.

| Шаг | Обработан узел | Глубина | Текущий максимум |
| --- | --- | --- | --- |
| 1 | `3` | 1 | 1 |
| 2 | `9` | 2 | 2 |
| 3 | `20` | 2 | 2 |
| 4 | `15` | 3 | 3 |
| 5 | `7` | 3 | 3 |

Ответ — `3`. Важная ошибка — выбрать меньшую глубину поддеревьев вместо большей. В дереве с путями `1 → 2 → 4 → 5` и `1 → 3` такой вариант вернёт `2`, хотя правильный ответ — `4`. В тестах есть этот контрпример.

## 3. Time Complexity

**Время: O(n)**, где `n` — число узлов. Все узлы обрабатываются по одному разу, а работа с одним узлом занимает O(1). Без просмотра дальней ветки нельзя быть уверенным, что в ней нет более глубокого листа.

**Дополнительная память: O(h)**, где `h` — высота дерева. Стек хранит узлы текущего спуска и ожидающие обработки соседние ветки. В худшем случае это O(n); для простой цепочки в этой реализации одновременно хранится один узел.

## 4. Reflection / Improvement

Время O(n) уже оптимально в худшем случае. Можно использовать обход по уровням с очередью и считать уровни: время останется O(n), а память станет O(w), где `w` — максимальная ширина дерева. Выбор зависит от формы дерева.

В тестах проверяются пустое дерево, один узел, ветки разной длины, повторяющиеся и отрицательные значения, цепочки из 10 000 узлов и 300 случайных деревьев. Случайные результаты сравниваются с короткой рекурсивной формулой. Проверяется также отсутствие изменений дерева. Это локальные тесты, а не результат отправки в LeetCode.
