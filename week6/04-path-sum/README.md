# 112. Path Sum

[Условие на LeetCode](https://leetcode.com/problems/path-sum/)

## 1. Problem

Нужно найти путь от корня до листа, сумма значений которого равна `targetSum`. Путь нельзя закончить во внутреннем узле. Для пустого дерева ответ `false`.

## 2. Approach

Используется обход в глубину с явным стеком. Вместе с узлом сохраняется сумма пути до него. Если извлечённый узел — лист и сумма совпала с целью, возвращается `true`. Иначе в стек добавляются дети с обновлёнными суммами. Если стек опустел, подходящего пути нет.

Трассировка для дерева `[5,4,8,11,null,13,4,7,2,null,null,null,1]`, цель `22`:

1. Начинаем с корня `5`, сумма `5`.
2. Переходим к `4`, сумма `9`; ветка через `8` остаётся в стеке.
3. Для узла `11` сумма становится `20`.
4. Лист `7` даёт `27` — продолжаем поиск.
5. Лист `2` даёт `22` — возвращаем `true`.

Главная тонкость — проверять сумму только в листе. Контрпример `[1,2]`, цель `1`, должен дать `false`. Ещё нельзя отбрасывать ветку, когда сумма превысила цель: `[5,-2]`, цель `3`, даёт `true`. Оба случая проверены в тестах.

## 3. Time Complexity

**Время: O(n) в худшем случае**, где `n` — число узлов. Каждый узел один раз добавляется в стек и извлекается из него, а работа с ним занимает постоянное время. При раннем совпадении поиск заканчивается раньше.

**Дополнительная память: O(h)**, где `h` — высота дерева. В стеке находятся отложенные ветки текущего пути; в худшем случае это `O(n)`. Сумма помещается в `int`: при ограничениях задачи её модуль не больше `5 000 000`.

## 4. Reflection / Improvement

В худшем случае нужно проверить все узлы, поэтому улучшить `O(n)` нельзя. Рекурсия сделала бы код короче, сохранив `O(n)` времени и `O(h)` памяти, но длинная цепочка может переполнить стек вызовов Java. Явный стек избегает этой проблемы.
