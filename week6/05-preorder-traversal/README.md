# 144. Binary Tree Preorder Traversal

[Условие на LeetCode](https://leetcode.com/problems/binary-tree-preorder-traversal/)

## 1. Problem

Нужно вернуть значения узлов в порядке: корень, левое поддерево, правое поддерево. Пустому дереву соответствует пустой список.

## 2. Approach

Решение использует стек. Извлечённый узел сразу записывается в результат. Затем в стек добавляется правый ребёнок, после него левый. Поскольку стек возвращает последний добавленный элемент первым, левое поддерево обрабатывается раньше правого.

Пример `[1,2,3,4,5]`; верх стека указан справа:

| Шаг | Извлечён узел | Стек после добавления детей | Результат |
| --- | --- | --- | --- |
| 1 | 1 | `[3,2]` | `[1]` |
| 2 | 2 | `[3,5,4]` | `[1,2]` |
| 3 | 4 | `[3,5]` | `[1,2,4]` |
| 4 | 5 | `[3]` | `[1,2,4,5]` |
| 5 | 3 | `[]` | `[1,2,4,5,3]` |

Легко перепутать порядок добавления детей. Если положить левого ребёнка первым, для `[1,2,3]` получится `[1,3,2]`. Тест с обоими детьми проверяет именно эту ошибку. `null` в стек не добавляется.

## 3. Time Complexity

**Время: O(n)**. Каждый узел один раз добавляется в стек, извлекается и записывается в список. Добавление в `ArrayList` занимает амортизированное `O(1)`.

**Дополнительная память: O(h)** для стека, где `h` — высота дерева. В нём хранятся ещё не обработанные ветки текущего пути. **С учётом результата память O(n)**: список содержит все `n` значений. Для пустого дерева используется `O(1)` памяти.

## 4. Reflection / Improvement

Быстрее `O(n)` по времени получить весь обход нельзя: нужно записать `n` значений. Обход Morris позволяет сократить вспомогательную память до `O(1)` при том же времени, временно изменяя ссылки дерева. Для этого понадобятся временные связи и их обязательное восстановление. Список результата всё равно занимает `O(n)`.
