# 145. Binary Tree Postorder Traversal

[Условие на LeetCode](https://leetcode.com/problems/binary-tree-postorder-traversal/)

## 1. Problem

Нужно собрать значения в порядке: левое поддерево, правое поддерево, корень. Каждый узел попадает в результат после своих детей.

## 2. Approach

Используются один стек, указатель `current` и ссылка `lastVisited`. Сначала спускаемся влево, сохраняя узлы в стеке. Когда спуск закончился, смотрим на вершину. Если её правое поддерево ещё не обработано, переходим туда. Иначе записываем узел в результат и запоминаем его в `lastVisited`.

Трассировка для `[1,null,2,3]`:

1. Кладём `1` в стек. Левого ребёнка нет, переходим к правому узлу `2`.
2. Кладём `2`, затем его левого ребёнка `3`.
3. У `3` нет детей: записываем `3`, снимаем его со стека.
4. У `2` нет правого ребёнка: записываем `2`.
5. Для `1` правый ребёнок уже равен `lastVisited`, поэтому записываем `1`. Ответ: `[3,2,1]`.

Сложность здесь — понять, когда правое поддерево уже пройдено. Сравнивать нужно ссылки на узлы, а не их значения. Например, в `[1,2,2]` левый и правый дети имеют одинаковые значения, но оба должны попасть в результат. Этот контрпример включён в тесты.

## 3. Time Complexity

**Время: O(n)**. Каждый узел один раз помещается в стек и один раз удаляется. Вершина проверяется постоянное число раз: до правого поддерева и после него. Добавление значений в список занимает суммарно `O(n)`.

**Дополнительная память: O(h)** — в стеке хранится путь от корня до текущего узла. `current` и `lastVisited` занимают `O(1)`. **С учётом списка результата память O(n)**. Здесь `n` — число узлов, `h` — высота дерева.

## 4. Reflection / Improvement

Время `O(n)` оптимально для полного обхода. Вариант с двумя стеками проще, но использует `O(n)` вспомогательной памяти. Morris postorder может дать `O(1)` вспомогательной памяти и `O(n)` времени, однако потребует временно менять и восстанавливать связи. Для этой задачи один стек понятнее и проще проверить.

## Проверка

Проверяются примеры, пустое дерево, одинаковые и отрицательные значения, цепочки, случайные деревья и отсутствие изменений дерева. Стресс-тест с 10000 узлами превышает лимит задачи и проверяет устойчивость итеративного решения. Результаты — в `week6/TEST_REPORT.md`.
