# 226. Invert Binary Tree

[Условие на LeetCode](https://leetcode.com/problems/invert-binary-tree/)

## 1. Problem

Нужно зеркально отразить дерево: у каждого узла поменять местами левое и правое поддеревья. Возвращается корень изменённого дерева.

## 2. Approach

Для обхода в глубину используется стек. Извлекаем узел, меняем ссылки `left` и `right` местами через временную переменную, затем добавляем существующих детей в стек. Новые узлы не создаются: дерево изменяется на месте.

Пример `[4,2,7,1,3,6,9]`:

1. У корня `4` меняем детей: слева становится `7`, справа `2`.
2. У узла `7` меняем детей `6` и `9`: слева `9`, справа `6`.
3. Узлы `9` и `6` — листья, их пустые ссылки остаются пустыми.
4. У узла `2` меняем детей `1` и `3`: слева `3`, справа `1`.
5. После обработки оставшихся листьев получаем `[4,7,2,9,6,3,1]`.

Недостаточно поменять детей только у корня. Цепочка `[1,2,null,3]` после полного отражения должна стать `[1,null,2,null,3]`; без обхода всех уровней узел `3` останется с неправильной стороны. Этот случай есть в тестах. Временная переменная нужна, чтобы не потерять одну из ссылок при обмене.

## 3. Time Complexity

**Время: O(n)**, где `n` — число узлов. Каждый узел извлекается из стека один раз; обмен ссылок и добавление детей занимают `O(1)`.

**Дополнительная память: O(h)** для стека, где `h` — высота дерева. Это верхняя оценка; для цепочки в данном обходе стек содержит только один узел. В общем худшем случае память может достигать `O(n)`. Результат использует существующее дерево, поэтому отдельная память под копию не нужна.

## 4. Reflection / Improvement

В худшем случае время меньше `O(n)` недостижимо: нужно изменить ссылки во всех внутренних узлах. Можно использовать рекурсию с теми же `O(n)` времени и `O(h)` памяти — код станет короче, но появится ограничение глубины стека вызовов. Обход по уровням также займёт `O(n)` времени, а очередь — `O(w)` памяти, где `w` — ширина дерева.
