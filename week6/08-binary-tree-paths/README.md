# 257. Binary Tree Paths

[Задача на LeetCode](https://leetcode.com/problems/binary-tree-paths/)

## 1. Problem

Нужно получить все пути от корня до листьев. Каждый путь записывается строкой, например `1->2->5`.

## 2. Approach

Обхожу дерево в глубину. В `StringBuilder` храню текущий путь. Перед переходом к узлу запоминаю длину строки, добавляю его значение, а после обработки возвращаю прежнюю длину. Так соседние ветки не смешиваются. Когда встречается лист, сохраняю готовую строку в ответ.

Для дерева `[1,2,3,null,5]` шаги такие:

1. Корень: путь `1`.
2. Переход влево: `1->2`.
3. Узел `5` — лист, сохраняю `1->2->5`.
4. Возвращаюсь к корню: в строке снова `1`.
5. Справа лист `3`, сохраняю `1->3`.

Главная сложность — правильно откатить строку после ветки. Если этого не сделать, второй путь станет продолжением первого. Проверка с двумя ветками и четырьмя листьями ловит эту ошибку. Также проверены одинаковые пути, отрицательные значения и цепочка из 100 узлов.

## 3. Time Complexity

**Time Complexity: O(n + L)**, где `n` — число узлов, а `L` — суммарное число символов в ответе. Каждый узел обрабатывается один раз, но готовые строки ещё нужно скопировать в результат. Поэтому просто `O(n)` здесь недостаточно; в худшем случае размер ответа достигает `O(n²)`.

**Space Complexity:** `O(h)` дополнительной памяти для рекурсии и текущей строки, плюс `O(L)` для ответа. `h` — высота дерева; длина записи одного значения ограничена условием.

## 4. Reflection / Improvement

Промежуточные строки можно собирать обычной конкатенацией, но это создаёт лишние копии. `StringBuilder` уже убирает эту работу. Быстрее `O(n + L)` в общем случае не получится: нужно прочитать дерево и записать ответ. Для очень глубоких деревьев рекурсию можно заменить стеком; по условию здесь не больше 100 узлов.
