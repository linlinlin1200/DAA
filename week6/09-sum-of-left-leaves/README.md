# 404. Sum of Left Leaves

[Задача на LeetCode](https://leetcode.com/problems/sum-of-left-leaves/)

## 1. Problem

Нужно сложить значения только тех листьев, которые являются левыми детьми своих родителей. Сам корень и правые листья в сумму не входят.

## 2. Approach

Обхожу дерево с помощью стека. Для каждого узла проверяю его левого ребёнка: если у ребёнка нет потомков, добавляю значение к сумме. Иначе продолжаю обход этой ветки. Правую ветку тоже нужно просматривать: внутри неё могут быть левые листья.

Пример `[3,9,20,null,null,15,7]`:

1. У `3` левый ребёнок `9` — лист, сумма становится `9`.
2. Перехожу к правому узлу `20`.
3. Его левый ребёнок `15` — лист, сумма становится `24`.
4. Правый лист `7` ничего не добавляет. Ответ: `24`.

Здесь легко перепутать левый узел и левый лист. Суммирование всех левых детей не работает: для `[1,2,3,4,null,5,6]` оно дало бы `11`, а правильный ответ `9`, потому что `2` — внутренний узел. Этот случай есть в тестах. Ещё проверены один корень, отрицательные значения и цепочки из 1000 узлов.

## 3. Time Complexity

**Time Complexity: O(n)**. Каждый узел рассматривается не больше одного раза, а проверка его детей занимает постоянное время.

**Space Complexity: O(h)** для стека, где `h` — высота дерева; в худшем случае это `O(n)`. Результат — одно число, поэтому для него нужна `O(1)` память. Входное дерево не меняется.

## 4. Reflection / Improvement

По времени решение уже оптимально: левый лист может находиться в любой ветке. Можно записать более короткий рекурсивный обход с той же сложностью. Обход Морриса позволяет получить `O(1)` дополнительной памяти, но требует временно менять ссылки дерева и здесь усложнил бы решение.
