# Week 6 — Binary Trees

Все 10 задач выполнены на Java. В папке каждой задачи лежат `Solution.java`, короткий отчёт `README.md` и локальные тесты `TestCases.java`.

| № | Задача | Время в худшем случае | Доп. память без результата |
| --- | --- | --- | --- |
| 1 | [Inorder Traversal](01-inorder-traversal/) | O(n) | O(h) |
| 2 | [Maximum Depth](02-maximum-depth/) | O(n) | O(h) |
| 3 | [Minimum Depth](03-minimum-depth/) | O(n) | O(w) |
| 4 | [Path Sum](04-path-sum/) | O(n) | O(h) |
| 5 | [Preorder Traversal](05-preorder-traversal/) | O(n) | O(h) |
| 6 | [Postorder Traversal](06-postorder-traversal/) | O(n) | O(h) |
| 7 | [Invert Binary Tree](07-invert-binary-tree/) | O(n) | O(h) |
| 8 | [Binary Tree Paths](08-binary-tree-paths/) | O(n + L) | O(h) |
| 9 | [Sum of Left Leaves](09-sum-of-left-leaves/) | O(n) | O(h) |
| 10 | [Merge Two Binary Trees](10-merge-two-binary-trees/) | O(n₁ + n₂) | O(h) |

`n` — число узлов, `h` — высота, `w` — максимальная ширина дерева. Для объединения `h` — высота результата. `L` — общее количество символов во всех возвращаемых строках путей; его нельзя игнорировать при оценке времени. Для значений типа `int` длина записи одного числа ограничена константой.

Списки обходов занимают O(n), строки путей — O(L), новое объединённое дерево — O(n₁ + n₂). Эта память результата учитывается отдельно от стека или очереди. Инверсия меняет исходное дерево; объединение создаёт независимое дерево.

## Запуск тестов

Нужен **JDK 17 или новее**, сторонних библиотек нет. Из корня репозитория:

```bash
java week6/RunTests.java
```

Команда отдельно компилирует каждую задачу и запускает её тесты. Это нужно, потому что у всех решений одинаковое имя класса `Solution`, как на LeetCode. Файлы компиляции сохраняются в `week6/.build/` и не попадают в Git.

Проверяются примеры, пустые деревья, один узел, цепочки, отрицательные и повторяющиеся значения. Случайные небольшие деревья сравниваются с отдельными эталонными реализациями. Для задач с большой допустимой глубиной есть проверки длинных цепочек. Ошибка останавливает общий запуск.

## Использование на LeetCode

Выбрать Java и вставить **только `Solution.java`** из нужной папки. Класс `TreeNode` LeetCode предоставляет сам; `common/TreeNode.java` и `common/TestSupport.java` нужны только для локальных тестов.

Локальная проверка не означает отправку в проверяющую систему LeetCode. Перед защитой стоит самостоятельно пройти примеры из README и разобраться, зачем в алгоритме нужен стек, очередь или проверка листа.
